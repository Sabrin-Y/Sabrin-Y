SQL Project

I used the MySQL world_db database to answer practical questions involving cities, countries, populations, life expectancy and geographical information.

01 · SQL PRACTICAL

World Database Analysis

The practical involved writing SQL queries and reviewing their outputs to investigate patterns within the world database. The exercises demonstrate how SQL can be used to retrieve specific records, identify extreme values, compare populations and combine information across related tables.

Count Cities in the USA

Counted the number of cities where the country code was USA. 

SELECT COUNT(*) AS Cities_in_USA
FROM city
WHERE CountryCode = 'USA';
Output: 274 cities

Highest Life Expectancy

Sorted countries by life expectancy to identify the highest value. 

SELECT Name, LifeExpectancy
FROM country
ORDER BY LifeExpectancy DESC
LIMIT 1;
Output: Andorra — 83.5

Find Cities Beginning with "New"

Used pattern matching to find city names beginning with a specific prefix. 

SELECT Name
FROM city
WHERE Name LIKE 'New%';
Technique: LIKE with a wildcard

Largest Cities

Sorted cities by population and limited the result to the first 10 records. 

SELECT Name, Population
FROM city
ORDER BY Population DESC
LIMIT 10;
Technique: ORDER BY + LIMIT

Cities Above 2 Million Population

Filtered the city table using a population threshold. 

SELECT Name, Population
FROM city
WHERE Population > 2000000;
Technique: WHERE with a comparison operator

Population Range

Identified cities with populations between 500,000 and 1,000,000. 

SELECT Name, Population
FROM city
WHERE Population BETWEEN 500000 AND 1000000;
Technique: BETWEEN range filtering

Most Populated City

Sorted city populations in descending order and returned the top record. 

SELECT Name, Population
FROM city
ORDER BY Population DESC
LIMIT 1;
Output: Mumbai (Bombay) — 10,500,000

City Name Frequency

Used COUNT and GROUP BY to calculate how often each city name appears. 

SELECT Name, COUNT(*) AS Frequency
FROM city
GROUP BY Name
ORDER BY Name ASC;
Technique: COUNT + GROUP BY + ORDER BY

Lowest Population City

Sorted cities by population in ascending order to identify the smallest population. 

SELECT Name, Population
FROM city
ORDER BY Population ASC
LIMIT 1;
Output: Adamstown — 42

Largest Country Population

Sorted countries by population to identify the largest population in the country table. 

SELECT Name, Population
FROM country
ORDER BY Population DESC
LIMIT 1;
Output: China — 1,277,558,000

Capital of Spain

Joined the country and city tables using their related key fields. 

SELECT city.Name AS Capital
FROM country
JOIN city
ON country.Capital = city.ID
WHERE country.Name = 'Spain';
Output: Madrid

Cities in Europe

Used a JOIN to connect city and country information and filtered the result by continent. 

SELECT city.Name AS City
FROM city
JOIN country
ON city.CountryCode = country.Code
WHERE country.Continent = 'Europe';
Technique: JOIN + WHERE filtering
What the practical demonstrates

The SQL exercises demonstrate the ability to move from a business question to a structured database query. Rather than relying on visualisations, the analysis uses SQL syntax to directly retrieve, filter, sort, aggregate and combine data.

Key Insights

The SQL practical produced a range of findings from the world database and demonstrated several different analytical techniques.

Population Analysis

SQL was used to identify the most and least populated cities, filter cities above 2 million people and investigate population ranges.

Geographical Analysis

Queries were used to find cities in Europe, identify the capital of Spain and search for cities using name-based conditions.

Aggregation

COUNT and GROUP BY were used to analyse city-name frequency, while AVG was used to investigate average population by country.

Relational Queries

JOIN operations connected the city and country tables, demonstrating how related data can be combined to answer more complex questions.

I also developed my understanding of database relationships, including primary and foreign keys and different types of JOINs. The workbook introduced INNER, LEFT, RIGHT, FULL, CROSS and SELF JOIN concepts before applying JOINs in the practical database exercises.


Overall, the project helped me understand how SQL can turn a business or analytical question into a precise query and return a focused result that can support decision-making.
